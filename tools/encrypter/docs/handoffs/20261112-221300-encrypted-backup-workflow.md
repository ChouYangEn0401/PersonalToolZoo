- **寫給接手的 agent**：這張把核心包成一條可重複執行的流程。全部可以用假資料夾與假版本庫離線測試。

## 需求（改寫，非原話）

- 把某個資料夾或某個版本庫專案打包、加密，輸出到可以上傳備份的位置；電腦中毒或資料毀損時要能救回來。

## 問題一句話

加密只是其中一步；備份要成立，還需要**多版本、完整性檢查、定期還原演練、與來源分離的存放位置**，而且檔名與附帶資訊不能洩漏內容。

## 結論先講

1. 流程固定五步：**打包 → 加密 → 讀回驗證 → 寫索引與校驗檔 → 放進輸出資料夾**；上傳由擁有者或另一個獨立步驟負責。
2. 至少三份、兩種位置、一份離線：本機輸出資料夾、私有的雲端位置（開啟版本保留）、一顆平常不插著的外接碟。
3. **加密過也不要放到公開的地方。**
4. 每次備份自動驗證；每月還原演練；每季在另一台電腦做完整救援演練（細節在第 3 張文件）。

## 流程

```
來源（資料夾／版本庫）
   │ 1 打包        版本庫 → 完整打包檔（含所有分支與標籤）並驗證；資料夾 → 排序固定的封存檔
   │               另外把「不在版本控制裡但重要」的檔案依允許清單打成第二包（例如設定與金鑰類檔案）
   │ 2 （選配）壓縮
   │ 3 加密        加密給「救援金鑰」與「日常金鑰」兩個收件者；本機只需要公鑰
   │ 4 讀回驗證     完整驗證一次；計算密文雜湊
   │ 5 索引與校驗   更新加密的索引；寫明文的密文校驗檔
   ▼
輸出資料夾（等待上傳）   →   （另一個步驟）上傳到私有位置   →   定期：輪替、演練
```

### 1. 打包

| 來源類型 | 做法 | 驗證 |
|---|---|---|
| 版本庫 | `git bundle create <檔> --all`：單一檔案、含完整歷史、所有分支與標籤 | `git bundle verify`；演練時再從打包檔複製出一份並檢查物件完整 |
| 版本庫裡沒被追蹤的重要檔案 | 依**明確的允許清單**另外打包（預設什麼都不帶；不要用「全部帶走再排除」） | 清單與實際帶走的檔案數一致 |
| 一般資料夾 | 排序固定的封存檔；排除清單（虛擬環境、建置產物、快取）寫在設定裡 | 封存檔可列出內容且檔案數相符 |

- 打包的暫存檔放在工具自己的資料夾（照這個 repo 的規則，不放使用者家目錄或系統暫存區），流程結束後刪除；
  失敗時也要清掉（暫存的打包檔是**明文**）。
- 版本庫的工作中變更（尚未提交的修改）不在打包檔裡：流程開始時檢查並在結果中提醒，不自動提交。

### 2. 加密

- 用新核心，加密給兩個收件者（救援、日常）。
- 一個來源一個加密檔；超過雲端或版本庫單檔上限時，由流程切成固定大小的分卷（切的是**密文**），索引記錄順序與各卷雜湊。

### 3. 讀回驗證

- 產生後立刻完整驗證。做備份的電腦只有公鑰時的做法：這次執行臨時產生一把只存在記憶體的金鑰，多加為一個收件者，
  用它讀回驗證後丟棄（檔頭會多一個無人能用的收件者欄位，無害）。若採用自有容器，則直接用還在記憶體裡的檔案金鑰讀回驗證。
  **這個小技巧需要在外部審閱時一併確認。**
- 驗證失敗＝這次備份失敗：刪掉輸出、回報、不動舊備份。

### 4. 命名、索引與校驗檔

- **檔名不帶內容資訊**：`<日期>-<隨機代號>.<副檔名>`，例如 `20261112-7f3a9c1e.bak`。不出現專案名、資料夾名、主機名。
  （日期可以再拿掉，改用純隨機代號；代價是人工整理比較不方便。預設保留日期。）
- **加密的索引**（和備份放一起）：每筆記錄隨機代號 ↔ 來源名稱、類型、時間、明文與密文的雜湊、大小、分卷、工具與格式版本、收件者指紋。
  每次備份更新索引並保留前幾版。索引本身也加密給同樣的收件者。
- **明文的校驗檔**：只有「檔名＋密文的雜湊」。不需要金鑰就能檢查備份有沒有壞，而且密文雜湊不洩漏內容。
- 每份加密檔的內容裡也帶一份自己的小清單（來源名稱、時間、雜湊），所以即使索引遺失，單一備份仍可獨立還原。

### 5. 多版本保留與輪替

| 層級 | 保留 |
|---|---|
| 每日 | 最近 7 份 |
| 每週 | 最近 4 份 |
| 每月 | 最近 12 份 |
| 每年 | 全部保留（或依空間決定） |

- **先確認新的成功，才刪舊的**；最新一份驗證失敗時不做任何輪替。
- 輪替只處理「輸出資料夾」這一份。遠端那一份的保留由遠端的版本保留功能負責——**本機的憑證不應該有能力刪除遠端的歷史版本**（見防勒索）。
- 內容沒有變化（明文雜湊與上一份相同）時不產生新備份，只在索引記一筆「已檢查、無變化」。

## 完整性檢查

| 時機 | 檢查 | 需要金鑰嗎 |
|---|---|---|
| 每次備份 | 讀回完整驗證；寫校驗檔 | 不需要解密金鑰（見上） |
| 上傳後 | 下載回來或用遠端提供的雜湊，比對校驗檔 | 不需要 |
| 每週（自動） | 輸出資料夾與外接碟上所有檔案對校驗檔 | 不需要 |
| 每月／每季 | 還原演練（第 3 張文件） | 需要 |

## 還會洩漏什麼（即使加密了）

| 洩漏 | 說明 | 處理 |
|---|---|---|
| 大小 | 加密檔大小約等於內容大小 | 可接受；在意時把多個來源合併成一包，或補到固定級距 |
| 數量與頻率 | 有幾個備份、多久一次、什麼時候有變化 | 可接受；固定排程可減少可推測的資訊 |
| 時間 | 檔名裡的日期、遠端的上傳時間、若用版本庫存放則有提交時間 | 可接受 |
| 帳號關聯 | 存放位置的帳號本身就說明了這是誰的 | 無法避免 |
| 收件者數量 | 檔頭看得到有幾個收件者 | 可接受 |
| 檔名 | 已用隨機代號處理 | — |

## 防勒索與防誤刪

勒索軟體與入侵者會去找備份並加密或刪除它。加密保護的是「內容不被看」，**不保護「備份不被毀」**。

1. **3-2-1**：三份、兩種媒介、一份不在這台電腦可及之處。
2. **權限分離**：上傳用的憑證只能「新增」，不能刪除或覆蓋舊版本；刪除歷史版本需要另一組平常不在這台電腦上的憑證（或只能在網頁上人工操作）。
3. **不可變或有版本保留的遠端**：選用有物件版本保留／鎖定的儲存，或至少開啟版本歷史與回收期。
4. **離線副本**：一顆外接碟，每月接上、同步、核對校驗檔、然後**拔掉**。長期插著的外接碟等於本機的一部分。
5. **來源與備份不同帳號可寫**（做得到的話）：輸出資料夾只給備份流程寫。
6. **異常偵測**：這次要備份的內容和上一份相比變動比例異常高（例如大部分檔案都變了）時，照樣備份但發出警告，並且**暫停輪替**，避免好的舊版本被壞的新版本擠掉。
7. 還原之後才發現中毒：保留的月備份與年備份就是為了這個情境。

## 和「上傳到私有雲端或私有版本庫」的關係

- **加密了也不要放公開的地方。** 公開之後無法收回；任何人可以永久保存密文，等密語被猜到、金鑰外洩、或演算法將來被削弱時再解；
  大小、時間、頻率等資訊也會一直累積。加密是最後一道防線，不是可以公開的理由。
- **私有的雲端儲存（有版本保留）**：適合當主要的遠端位置。
- **私有的版本庫**：只適合小的備份（例如幾 MB 的設定與金鑰包）。理由：版本庫會永久保留每一版的二進位檔，容量只增不減；
  代管平台對單檔與版本庫大小有限制（本次查到某主流平台：單檔超過 50 MiB 警告、超過 100 MiB 拒絕，建議版本庫小於 1 GB）；
  有推送權限的憑證通常也能強制覆寫歷史，要另外開啟保護設定才擋得住。
- 上傳步驟**不在這個工具裡做**：工具只負責把檔案放進輸出資料夾並產生校驗檔。這樣加密工具永遠不需要網路權限，也不持有雲端憑證。
- 上傳之前再確認一次：輸出資料夾裡只有加密檔、加密的索引、校驗檔，沒有任何明文暫存檔。

## 指令（暫定）

```
encrypter-cli backup run     --source <路徑> --profile <名稱> [--json]   # 打包→加密→驗證→索引→輸出
encrypter-cli backup list    [--json]                                    # 需要金鑰才能顯示來源名稱；否則只列代號
encrypter-cli backup check   [--json]                                    # 對校驗檔，不需要金鑰
encrypter-cli backup rotate  [--dry-run] [--json]                        # 依保留規則；預設只列出會刪什麼
encrypter-cli backup restore --id <代號> --out <資料夾> (...金鑰來源...) [--json]
encrypter-cli backup drill   (...金鑰來源...) [--json]                   # 每月演練：解到暫存、比對、清掉、寫演練紀錄
```

設定檔只放：來源清單、允許與排除清單、輸出資料夾、保留規則、收件者公鑰。**不放任何祕密。**

## 選項表（遠端位置）

| 選項 | 內容 | 建議 |
|---|---|---|
| A | 私有雲端儲存（開啟版本保留）＋每月一次的離線外接碟 | **建議（預設）** |
| B | 私有版本庫（只放小型的設定與金鑰包）＋離線外接碟 | 可行，限小檔 |
| C | 只有離線外接碟 | 可行但只有一個遠端副本，火災或失竊時一起沒有 |

## 驗收

- [ ] 用假版本庫與假資料夾跑完整流程：產生加密檔、加密索引、校驗檔；輸出資料夾沒有任何明文
- [ ] 還原出來的版本庫通過打包檔驗證，內容與來源的提交雜湊一致；還原出來的資料夾逐檔雜湊一致
- [ ] 輸出的檔名與明文校驗檔裡找不到來源名稱、主機名、使用者名稱
- [ ] 竄改或截斷任一輸出檔後，`backup check` 與 `backup drill` 都會失敗並指出是哪個代號
- [ ] 最新備份驗證失敗時，輪替不刪任何東西；`rotate` 預設是演習模式
- [ ] 流程中途強制中斷後，沒有留下明文暫存檔（下次執行會清理並回報）
- [ ] 流程不連網、不開網路埠；設定檔與輸出裡沒有任何祕密
- [ ] 刪掉索引後，仍能只靠單一加密檔＋金鑰還原該筆備份

## 不要做的事

- 不要在這個工具裡實作上傳、同步或任何網路功能。
- 不要把來源名稱、主機名放進檔名或明文校驗檔。
- 不要在新備份驗證通過之前刪除任何舊備份。
- 不要自動提交、自動清理來源版本庫，或更動來源資料夾的任何內容。
- 不要把金鑰、密語或救援資訊放進備份包（循環依賴），也不要放進設定檔。
- 不要用真實的專案或真實資料做開發期測試。
- 不要把「加密過」當成可以上傳到公開位置的理由。
